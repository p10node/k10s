**A one-line install, twice the resource coverage, and a command language
worth learning once.** The biggest release since the first tag — and the one
that turns k10s from "a demo you can run" into something you install.

## Install in one line

```bash
curl -fsSL https://p10node.com/k10s/install.sh | sh
```

macOS and Linux, `amd64` and `arm64`. It picks the right prebuilt binary,
verifies its sha256 against the release manifest, and installs into
`/usr/local/bin` — or `~/.local/bin` when that would need a password it
cannot ask for. `--dir`, `--version` and `--no-sudo` are documented, together
with the matching `uninstall.sh`, in
[docs/install.md](https://github.com/p10node/k10s/blob/v0.1.1/docs/install.md).
Read the script before you pipe it to a shell; it is short on purpose.

Windows stays on the [release page](https://github.com/p10node/k10s/releases)
— the installer sends you there rather than pretending.

## 30 kinds, in groups that fold

Up from 16. **Workloads · Network · Config · Storage · RBAC · Cluster ·
Custom Resources**:

Pods · Deployments · ReplicaSets · StatefulSets · DaemonSets · Jobs ·
CronJobs · HPAs · Services · Endpoints · Ingresses · NetworkPolicies ·
ConfigMaps · Secrets · ResourceQuotas · LimitRanges · PDBs · PVCs · PVs ·
StorageClasses · ServiceAccounts · Roles · RoleBindings · ClusterRoles ·
ClusterRoleBindings · Nodes · Namespaces · Events · CRDs · Custom Resources

Groups fold with `space`, `left`, or a click on the header, and stay folded
across restarts (Config, Storage and RBAC start that way). **A folded group
asks your cluster for nothing** — the sidebar decides what gets counted, and
counting is one `limit=1` request per *visible* kind, six at a time, with
refusals remembered so a kind you cannot list is never asked twice.

## `/` is k10s, `:` is the cluster

The prompt now speaks k9s's vocabulary where k9s has one, and keeps k10s's
own settings on the other prefix.

```
/theme   /settings   /update   /version   /help        k10s itself

:po  :deploy  :rs  :sts  :ds  :job  :cj  :hpa      workloads
:svc  :ep  :ing  :netpol                           network
:cm  :sec  :quota  :limits  :pdb                   config
:pvc  :pv  :sc                                     storage
:sa  :role  :rb  :crole  :crb                      rbac
:no  :ns  :ev  :crd  :cr                           cluster + custom
```

- Every kind also answers to its plural **and** singular — `:pods`, `:pod`,
  `:persistentvolumes`. `:aliases` prints the whole list.
- `:po kube-system` opens that kind in that namespace (`all` works); an
  argument that is not a namespace filters instead — `:svc api`.
- Namespace and context moved to `:ns` / `:ctx`, with or without a name.
- **Anything that is not a `/` or `:` command runs as a shell command** and
  its output opens in the main panel: `date`, `kubectl get pods -o wide`,
  `helm list`. Through your own `$SHELL`, capped at 30 s, with no terminal
  attached — use `s` on a pod when you want an interactive one.

Breaking: `/ns`, `/context` and `:mouse` are gone — they are `:ns`, `:ctx`
and `ctrl+s`.

## No setup screen

First run opens the cluster. The onboarding dialog that used to ask what you
call kubectl is gone; every setting has a working default and `/settings` is
one keystroke away when you want to change one. k10s opens on **kubeconfig's
current-context** — the cluster `kubectl` would talk to — and `:ctx <name>`
switches for the session without writing to kubeconfig.

## AI is switched off in this build

`ctrl+a`, the `[ AI ]` badge and the provider fields in `/settings` now open
a modal saying so instead of running. The assistant answers with a live
cluster's context attached, against whatever endpoint and key are configured,
and that is not something to ship half-finished while it is being reworked.
The code stays in the tree — one constant turns it back on — and it returns
when the rework lands.

## Install / upgrade

Already running k10s? `k10s update` (or `/update`) — checksum-verified,
atomic, offers to restart into the new binary.

```bash
curl -fsSL https://p10node.com/k10s/install.sh | sh
go install github.com/p10node/k10s@latest
shasum -a 256 -c checksums.txt --ignore-missing
```

`checksums.txt` proves the download matches what this release published — not
who published it. Signing is still on the list.
