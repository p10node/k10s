**Themes are now yours.** Drop a YAML palette into `~/.k10s/themes`, restart, and it sits in the same picker as the seven built-ins — same live preview, no rebuild, no fork.

## Custom themes

```bash
mkdir -p ~/.k10s/themes
curl -fsSL https://raw.githubusercontent.com/p10node/k10s/v0.1.2/examples/themes/rose-pine.yaml \
  -o ~/.k10s/themes/rose-pine.yaml
k10s   # /theme → preview rose-pine → enter
```

- **Twelve required fields, all `#RRGGBB`.** Copy
  [`examples/themes/rose-pine.yaml`](https://github.com/p10node/k10s/blob/v0.1.2/examples/themes/rose-pine.yaml),
  rename, replace the colors. The picker generates its swatch from the palette,
  so nothing else needs touching.
- **`.yaml` and `.yml` are both loaded at startup**, appended after the
  built-ins in `/theme` and in the `T` / `ctrl+t` cycle.
- **Strict parsing, soft failure.** A bad color, an unknown field, a name that
  collides with a built-in — that one file is skipped and named in the status
  bar; every other custom theme still loads and the TUI still starts. A theme
  saved in `config.yaml` that later disappears falls back to `tokyo-night`.
- **The folder follows your config.** Normally `~/.k10s/themes`, beside
  `config.yaml`; it moves with `K10S_CONFIG`, and `K10S_THEME_DIR` overrides it
  outright.

Full guide: [docs/themes.md](https://github.com/p10node/k10s/blob/v0.1.2/docs/themes.md)

## Also in this release

- **The theme picker scrolls.** With an unbounded list it now keeps the
  selected row in a viewport and shows `3–12/19` in the title, instead of
  growing past the bottom of your terminal.
- **`theme → x (saved)` only appears when the write actually succeeded.**

## Install / upgrade

Already running k10s? `/update` — checksum-verified, atomic, offers to restart
into the new binary.

```bash
go install github.com/p10node/k10s@latest
```

Or take a binary below: macOS (Intel / Apple Silicon), Linux (amd64 / arm64),
Windows (amd64). One static binary, no dependencies.

```bash
shasum -a 256 -c checksums.txt --ignore-missing
```

`checksums.txt` proves the download matches what this release published — it
says nothing about *who* published it. Signing is still on the list.

Friction reports remain the most useful thing you can send:
https://github.com/p10node/k10s/issues
