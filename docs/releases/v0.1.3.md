**Your k9s plugins run here.** k10s reads the core k9s `plugins.yaml` format:
scope a command to a view, give it a shortcut, and it shows up in the Actions
pane beside the built-in verbs — listed, labelled, and clickable, like
everything else in k10s.

## Command plugins

```bash
mkdir -p ~/.k10s
curl -fsSL https://raw.githubusercontent.com/p10node/k10s/v0.1.3/examples/plugins.yaml \
  -o ~/.k10s/plugins.yaml
k10s   # select a pod → ctrl+L is now "Pod logs via kubectl"
```

```yaml
plugins:
  restart-deployment:
    shortCut: Shift-R
    description: Rollout restart
    scopes: [deploy]
    command: kubectl
    confirm: true
    dangerous: true
    args: [rollout, restart, deployment/$NAME, -n, $NAMESPACE, --context, $CONTEXT]
```

- **Discoverable, not memorised.** Applicable plugins are appended to the
  Actions pane for the selected object, with their shortcut next to them, and
  run on click as well as on key.
- **Two locations.** `~/.k10s/plugins.yaml`, then every `.yaml` / `.yml` under
  `~/.k10s/plugins/` recursively — later files override an earlier plugin of
  the same name. `K10S_PLUGINS` and `K10S_PLUGIN_DIR` override both, and both
  follow `K10S_CONFIG` when it points elsewhere. k10s never rewrites your
  plugin files.
- **k9s notation for shortcuts** (`Ctrl-L`, `Shift-R`, `Alt-X`, `x`) and k9s
  scopes (`po`, `deploy`, `svc`, … or `all`). Built-in keys win a collision
  unless the plugin says `override: true`.
- **`confirm` for a modal, `dangerous` for red, `background` for detached.**
  Foreground commands leave the alternate screen and inherit the real
  terminal, so `fzf` and other interactive tools work.
- **Variables:** `$NAME`, `$NAMESPACE`, `$CONTEXT`, `$CLUSTER`,
  `$RESOURCE_NAME`, `$FILTER`, `$KUBECONFIG`, `$USER`, `$GROUPS`, and
  `$COL-<COLUMN>` for any displayed column (`$COL-STATUS`). Unknown ones such
  as `$HOME` are left intact, so `sh -c` can expand them itself.
- **A malformed plugin never costs you the TUI.** It is skipped, its filename
  and validation error go to the status bar, and k10s starts.

Full guide and field table:
[docs/plugins.md](https://github.com/p10node/k10s/blob/v0.1.3/docs/plugins.md)

### What a plugin is allowed to do

A plugin runs an arbitrary executable on your machine with your kubeconfig, no
sandbox. Read a `plugins.yaml` before you install it, exactly as you would in
k9s — `confirm: true` is a courtesy to yourself, not a boundary.

## Not yet

- `pipes`, `inputs`, `overwriteOutput` — the newer k9s-only fields — are not
  implemented.
- `$RESOURCE_GROUP`, `$RESOURCE_VERSION`, `$CONTAINER`, `$POD` parse for
  compatibility but expand empty; the table model does not carry them yet.

## Install / upgrade

`/update` from inside k10s — checksum-verified, atomic, offers to restart into
the new binary.

```bash
go install github.com/p10node/k10s@latest
```

Or a binary below: macOS (Intel / Apple Silicon), Linux (amd64 / arm64),
Windows (amd64).

```bash
shasum -a 256 -c checksums.txt --ignore-missing
```

`checksums.txt` matches the download to what this release published; it is not
a signature of who published it.

Issues and friction reports: https://github.com/p10node/k10s/issues
