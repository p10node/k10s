**Sample data no longer stands in for your cluster.** k10s used to fall back
to its bundled demo whenever a connection failed — so a machine with no
kubeconfig opened onto forty pods, three nodes and a CrashLoopBackOff that
existed nowhere, labelled only by one line in the status bar. That is fixed:
the demo is something you ask for by name, and "no cluster" says so.

## The demo is a context, not a mode ([#2](https://github.com/p10node/k10s/pull/2))

```bash
k10s demo     # the sample cluster — fake data, clearly labelled
k10s          # your real cluster, or "No cluster" if there isn't one
```

- `k10s demo` opens on it, `/demo` switches to it from anywhere, and `:ctx`
  always lists it as `k10s demo · sample data` with a legend under the list.
- **To leave it, pick any other context.** There is no separate exit, because
  there is no mode to exit.
- While it is up the header carries a `DEMO` marker, so no frame of it can be
  screenshotted or mistaken for a real cluster.

## The "No cluster" panel ([#2](https://github.com/p10node/k10s/pull/2))

With no kubeconfig, or a context whose API server does not answer, the main
panel now names the reason and points at the way out:

| Key      | Action                                                  |
|----------|---------------------------------------------------------|
| `r`      | retry the connection (rebound while the panel is up)     |
| `enter`  | same — retry                                             |
| `:ctx`   | pick another kubeconfig context                          |
| `/setup` | installing kubectl, getting a `~/.kube/config` — links   |
| `/demo`  | try the UI on the sample cluster                         |

Two different failures land there and both count as "no cluster": kubeconfig
that will not load or name a context, and **a context whose server never
answers**. The second is the less obvious one — client-go is lazy, so a
deleted cluster or a downed VPN builds a perfectly healthy client that simply
never returns rows. k10s now checks the server-version handshake up front and
sends that case to the panel instead of to an empty table. A `401`/`403` is
deliberately *not* treated as unreachable: that is a live cluster refusing
this user, and k10s connects so you see whatever you are allowed to.

Long client-go errors are trimmed to their first useful clause, so the panel
reads as a reason rather than as advice for a different tool.
[docs/cluster-setup.md](https://github.com/p10node/k10s/blob/v0.1.4/docs/cluster-setup.md)
is the same guide, longer.

## Fixes from [#1](https://github.com/p10node/k10s/pull/1) — thanks, [@clamshell2000](https://github.com/clamshell2000)

The first outside contribution to k10s, and it fixed two things that made the
UI feel broken after handing the terminal to another program:

- **The mouse comes back after `$EDITOR` exits.** Bubble Tea's cell-motion
  tracking is re-enabled on return, so rows, navigation and actions stay
  clickable — while an intentional `ctrl+s` copy mode is left alone. Same
  treatment for foreground plugin commands.
- **`$EDITOR` is parsed properly.** Quotes and backslash escapes are honoured,
  so `code --wait` and editor paths with spaces work — without involving a
  shell, and without shell expansion.
- **Startup no longer reports a connection it does not have** when the server
  version handshake fails; that error now surfaces instead of being swallowed.

## Also

- `:mouse` is now `/mouse` — toggling capture is k10s, not the cluster.
- `just screenshot` and `cmd/shot` run against the demo context explicitly,
  so every frame in the docs is honestly labelled sample data.

## Upgrading

Two behaviour changes worth knowing before you upgrade:

1. **Plain `k10s` no longer falls back to the demo.** Scripts or habits that
   relied on it always showing *something* should use `k10s demo`.
2. `:mouse` is gone; use `/mouse` or `ctrl+s`.

`/update` from inside k10s — checksum-verified, atomic, offers to restart into
the new binary.

```bash
curl -fsSL https://p10node.com/k10s/install.sh | sh
go install github.com/p10node/k10s@latest
shasum -a 256 -c checksums.txt --ignore-missing
```

`checksums.txt` matches the download to what this release published; it is not
a signature of who published it.
