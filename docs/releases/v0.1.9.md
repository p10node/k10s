**k10s installs with Homebrew now**, it runs on the Kubernetes 0.37 client
libraries and Bubbles 1.0, and every direct dependency is at its newest
release.

## Homebrew ([#29](https://github.com/p10node/k10s/pull/29), [#26](https://github.com/p10node/k10s/issues/26))

```bash
brew install p10node/tap/k10s
```

The formula in [p10node/homebrew-tap](https://github.com/p10node/homebrew-tap)
installs this release's prebuilt archive for macOS and Linux, arm64 and amd64,
checked against the sha256 that this release's `checksums.txt` lists, so no Go
toolchain is needed. From this release on, the release workflow updates the
formula by itself, after checking each archive against `checksums.txt` and its
build provenance attestation.

A k10s that Homebrew installed leaves upgrades to Homebrew: `k10s update`
prints `installed by Homebrew, which updates it: run brew upgrade k10s` and
changes nothing, and `/update` says the same. Installing by the full name, as
above, trusts the formula by itself; by short name, run `brew trust --formula
p10node/tap/k10s` first ([Tap Trust](https://docs.brew.sh/Tap-Trust)).

## Kubernetes client libraries 0.37 ([#20](https://github.com/p10node/k10s/pull/20))

client-go and the k8s.io modules released with it move together from v0.36.4
to v0.37.2: api, apimachinery, apiextensions-apiserver, client-go, kubectl,
metrics and streaming.

## Bubbles 1.0 ([#21](https://github.com/p10node/k10s/pull/21), [#31](https://github.com/p10node/k10s/pull/31))

The terminal UI's component library, charmbracelet/bubbles, moves from v0.21.0
to v1.0.0, and charmbracelet/x/ansi from v0.10.2 to v0.11.9. Bubbles 1.0 pads
an empty text input with spaces that carry no style, which showed the
terminal's own background after the placeholder on the prompt row, the empty
palette query and the /settings custom row. k10s paints that padding with the
theme background again, so nothing should look different.

## Upgrading

Nothing changes behaviour, except that a Homebrew install leaves its upgrades
to `brew upgrade k10s`. If you installed v0.1.8 with Homebrew, upgrade it with
`brew upgrade k10s` rather than `/update`: v0.1.8 does not know about Homebrew
yet and would write over the formula's copy.

govulncheck reports none for this release.

`/update` from inside k10s, checksum-verified, atomic, offers to restart into
the new binary.

```bash
curl -fsSL https://p10node.com/k10s/install.sh | sh
brew install p10node/tap/k10s
go install github.com/p10node/k10s@latest
gh attestation verify k10s_v0.1.9_<os>_<arch>.tar.gz --repo p10node/k10s   # .zip on Windows
```
